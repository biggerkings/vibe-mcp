## 二、什么是 MCP

### 2.1 MCP 定义

**MCP（Model Context Protocol）** 是 **模型上下文协议** 的缩写，由 Anthropic 推出的开放标准。

它是一套让 AI 助手与外部工具、服务、数据源进行**标准化连接**的协议。

#### 有无 MCP 的区别

| 场景 | 没有 MCP | 有了 MCP |
|:---|:---|:---|
| 信息获取 | AI 只能根据输入文字和已有上下文回答 | AI 可访问外部系统，读取设计稿、文档库、代码仓库 |
| 工具调用 | AI 只能"对话" | AI 可以"读取信息、调用工具、执行操作" |
| 上下文更新 | 靠手动复制粘贴 | 按需动态读取，实时同步 |

### 2.2 MCP 解决的核心问题

| 问题 | MCP 带来的改进 |
|:---|:---|
| AI 看不到外部系统数据 | 通过 MCP 连接数据源或工具 |
| 每个平台接法都不同 | 用统一协议描述工具与资源 |
| AI 不能直接操作外部能力 | 通过标准化工具调用执行任务 |
| 上下文靠手动复制粘贴 | 可按需动态读取上下文 |

### 2.3 MCP 的核心组成

```
┌─────────────────────────────────────────────────────────┐
│                      MCP 架构体系                        │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────┐      ┌──────────────┐      ┌─────────┐ │
│  │  MCP Client  │◄────►│  MCP Server  │◄────►│ External│ │
│  │  (Cursor等)   │      │  (工具服务)   │      │ Systems │ │
│  └──────────────┘      └──────────────┘      └─────────┘ │
│         │                      │                         │
│         ▼                      ▼                         │
│  ┌──────────────┐      ┌──────────────┐                  │
│  │   Tools      │      │  Resources   │                  │
│  │  (功能按钮)   │      │  (可读取数据) │                  │
│  └──────────────┘      └──────────────┘                  │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### 1) MCP Client

使用 MCP 的 AI 客户端：
- Cursor、Claude Desktop、Trae、LingMa

**职责**：
- 与用户对话
- 展示可用工具
- 把 AI 的工具调用请求转发给 MCP Server

#### 2) MCP Server

提供能力的工具服务端。

以 **MasterGo MCP** 为例，提供的能力：

| 接口 | 功能 |
|:---|:---|
| `getDSL` | 获取图层数据，返回设计稿的结构化表示 |
| `getComponentLink` | 获取组件文档链接，支持基于组件库的代码生成 |
| `getMeta` | 获取设计稿元信息 |

#### 3) 能力类型

- **Tools**：可被调用的操作（"搜索文档"、"读取设计稿"）
- **Resources**：可被读取的资源（文档、配置、知识条目）
- **Prompts**：可复用的提示模板

### 2.4 MCP 工作流程

```
用户: "根据设计稿生成登录页"
  │
  ▼
AI: 判断需要调用 MasterGo MCP
  │
  ▼
Client: 发送请求给 MCP Server
  │
  ▼
MasterGo MCP: 返回设计稿 DSL 数据
  │
  ▼
AI: 基于 DSL 生成代码
  │
  ▼
用户: 获得贴近设计稿的代码
```

**关键点**：AI 并不是"直接懂了所有信息"，而是通过 MCP **按需获取上下文**。

### 2.5 MCP vs API

| 对比项 | API | MCP |
|:---|:---|:---|
| 定位 | 程序与程序之间的调用接口 | AI 客户端与工具生态之间的标准协议 |
| 使用者 | 程序员、系统 | AI 客户端 |
| 底层实现 | 直接调用 | 很多 MCP Server 底层仍在调用 API，但统一了对 AI 的暴露方式 |

**结论**：MCP 不是用来替代 API，而是让 AI 更容易、更标准地使用 API。

### 2.6 MCP 对开发工作的价值

| 价值点 | 说明 |
|:---|:---|
| 减少手工搬运上下文 | 不必频繁复制设计稿、文档、接口说明 |
| 提升回答准确性 | AI 基于实时数据回答，而非猜测 |
| 增强自动化能力 | AI 可以读取、查询、分析甚至执行操作 |
| 改善协作效率 | 设计、研发、文档通过统一入口协同 |
| 适合复杂项目 | 多系统依赖时，显著提升 AI 可用性 |

### 2.7 一句话总结

> **MCP 是一种让 AI 安全、标准化地连接外部工具和上下文的协议。**

它让 AI 从"只会聊天"升级为"能结合真实环境完成任务"的工作助手。

## 三、UI 代码 Skills

### 3.1 什么是 Agent Skill

**Skill** 是 Cursor 中的一种可复用 AI 能力配置，它：
- 定义了 AI 在特定场景下的行为方式
- 包含专业的领域知识和最佳实践
- 可以项目级别或用户级别复用

### 3.2 frontend-design Skill

我们项目中使用的 `frontend-design` skill 专注于创建**独特、生产级**的前端界面。

#### 核心设计理念

**避免"AI 平庸设计"** —— 拒绝千篇一律的 AI 生成风格，追求有特色的视觉表达。

#### 设计思维框架

在编码前，先明确四个维度：

| 维度 | 问题 | 示例方向 |
|:---|:---|:---|
| **Purpose** | 解决什么问题？谁使用？ | 旅游预订、后台管理、社交应用 |
| **Tone** | 选择什么风格？ | 极简主义、复古未来主义、有机自然、奢华精致、 playful |
| **Constraints** | 技术约束？ | Vue/React、性能要求、无障碍需求 |
| **Differentiation** | 什么让人难忘？ | 独特的交互、视觉符号、动效 |

**关键原则**：选择清晰的概念方向，并精准执行。

#### 美学指导原则

| 要素 | 要求 |
|:---|:---|
| **Typography** | 避免通用字体（Arial、Inter），选择独特、有个性的字体组合 |
| **Color & Theme** | 使用 CSS 变量保持一致性，主导色 + 鲜明点缀色 |
| **Motion** | CSS 动画实现微交互，页面加载时编排好的交错出现效果 |
| **Spatial Composition** | 非对称布局、重叠元素、对角线流动、破格网格 |
| **Backgrounds & Details** | 渐变网格、噪点纹理、几何图案、分层透明度、戏剧性阴影 |

#### 禁止使用的"AI 平庸元素"

- 过度使用的字体（Inter、Roboto、Arial、系统字体）
- 陈词滥调的色彩方案（紫色渐变 + 白色背景）
- 可预测的布局模式
- 缺乏场景特色的通用设计

### 3.3 UI Audit Skill

另一个重要的 skill 是 `ui-audit`，用于自动化 UI 审查。

#### 审查维度

| 维度 | 检查内容 |
|:---|:---|
| **Visual Hierarchy** | 标题层级、CTA 突出度、内容分组、阅读流、字阶 |
| **Visual Style** | 间距一致性、色彩使用、阴影/深度、排版、动效 |
| **Accessibility** | 键盘导航、焦点状态、对比度、触摸目标、屏幕阅读器 |
| **Navigation** | 位置指示、菜单结构、面包屑、移动端适配 |
| **Usability** | 功能可发现性、反馈、错误处理、认知负荷 |

#### 决策工作流

```
1. WEIGH INFORMATION
   ├─ 机构知识（现有模式、品牌规范）
   ├─ 用户熟悉度（竞品模式、平台惯例）
   └─ 研究数据（用户测试、分析数据）

2. NARROW OPTIONS
   ├─ 消除与约束冲突的选项
   ├─ 按宏观赌注优先级排序
   └─ 选择支持 JTBD 的方案

3. EXECUTE
   └─ 应用相关检查清单 + 模式
```

## 四、生产力工具介绍

### 4.1 看板工具

专为 **AI 辅助开发** 设计的看板工具，核心能力：

#### 1) 并行运行多 AI 编码代理

支持同时接入：
- Claude、ChatGPT、Gemini
- OpenCode、Cursor、Amp
- Copilot、Windsurf

**收益**：消除单个代理的空闲等待，可随时切换审查。

#### 2) 三步工作流

```
┌─────┐    ┌───────┐    ┌────────┐
│ Plan │ -> │ Prompt │ -> │ Review │
└─────┘    └───────┘    └────────┘
  │           │            │
  ▼           ▼            ▼
规划任务    AI自动编码    审查差异
设置优先级  生成代码      评论修正
```

#### 3) 任务管理与分解

- ✅ 子任务拆分：大任务拆分为可并行开发的子任务
- ✅ 信息可视化：任务卡片显示优先级、状态
- ✅ 状态自动追踪：PR 创建/合并时自动更新

#### 4) 内置代码审查 & QA

- 📋 查看代码差异（diff）和语法高亮
- 💬 对 AI 生成的代码进行评论
- 🌐 内置浏览器直接测试网站
- 🔄 从任何 PR 启动工作树并迭代修改

#### 5) Git 工作流自动化

- 🔀 自动创建 git worktrees
- ⚙️ 运行本地设置脚本
- 💻 多工作区并行开发，互不干扰

### 4.2 MasterGo MCP 详细能力

#### DSL 转换引擎流程

```
设计稿
   │
   ▼
┌─────────────┐
│ 数据拉取    │  MasterGo API 获取全量原始数据
└─────────────┘
   │
   ▼
┌─────────────┐
│ 数据清洗    │  过滤冗余、统一格式、标准化
└─────────────┘
   │
   ▼
┌─────────────┐
│ 语义注入    │  注入前端领域语义（组件类型、样式变量）
└─────────────┘
   │
   ▼
┌─────────────┐
│ 结构化输出  │  平台无关的 DSL（JSON 格式）
└─────────────┘
   │
   ▼
前端代码
```

#### AI 智能增强特性

| 特性 | 说明 |
|:---|:---|
| ✨ 样式优化 | 自动识别并合并冗余样式 |
| 📝 结构优化 | 优化代码组织结构 |
| 🎯 交互推断 | 智能推断基础交互逻辑 |
| ✅ 规范校验 | 确保代码符合团队编码规范 |

### 4.3 其他有用的 MCP 工具

#### 1) Apifox MCP

**官网**: https://docs.apifox.com/apifox-mcp-server

**用途**：API 接口管理与代码生成

**使用示例**：
```
"通过 Apifox MCP 读取 /user 前缀的接口，
 生成相关 TypeScript 类型定义，
 参考接口样板文件 @api/types.ts"
```

**能力**：
- 读取接口文档
- 生成请求/响应类型
- 自动生成 API 调用代码

#### 2) 浏览器自动化 MCP (cursor-ide-browser)

**用途**：浏览器自动化测试与页面检查

**能力**：

| 工具 | 功能 |
|:---|:---|
| `browser_navigate` | 页面导航 |
| `browser_click` | 元素点击 |
| `browser_type` | 文本输入 |
| `browser_snapshot` | 获取页面结构 |
| `browser_take_screenshot` | 截图 |
| `browser_scroll` | 页面滚动 |
| `browser_profile_start/stop` | 性能分析 |

**使用场景**：
- 自动生成页面截图对比设计稿
- 自动化测试用户流程
- 性能分析与优化

#### 3) GitHub/GitLab MCP

**用途**：代码仓库操作

**能力**：
- 读取代码文件
- 创建 PR/Issue
- 代码搜索
- 审查评论

#### 4) 数据库 MCP

**用途**：数据库查询与管理

**能力**：
- 执行 SQL 查询
- 查看表结构
- 数据迁移
- 生成 ORM 代码
