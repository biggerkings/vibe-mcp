# 什么是 MCP

## 一、MCP 是什么

**MCP** 是 **Model Context Protocol** 的缩写，中文通常可理解为 **模型上下文协议**。

它是一套让 AI 助手与外部工具、服务、数据源进行标准化连接的协议。通过 MCP，像 Cursor、Claude Desktop、Trae 这类支持 MCP 的客户端，可以把原本只会“对话”的 AI，扩展成能够“读取信息、调用工具、执行操作”的智能助手。

简单来说：

- **没有 MCP**：AI 只能根据你输入的文字和已有上下文回答问题。
- **有了 MCP**：AI 可以进一步访问外部系统，例如设计稿、文档库、代码仓库、数据库、浏览器、工单系统等。

---

## 二、为什么需要 MCP

传统 AI 对话存在一个常见限制：**模型本身不知道你本地电脑、企业系统或第三方平台里的实时信息**。  
MCP 的作用，就是给 AI 提供一个统一的“连接层”，让它在合适的边界内获取更多上下文并执行工具调用。

MCP 主要解决以下几个问题：

| 问题 | MCP 带来的改进 |
|------|----------------|
| AI 看不到外部系统数据 | 通过 MCP 连接数据源或工具 |
| 每个平台接法都不同 | 用统一协议描述工具与资源 |
| AI 不能直接操作外部能力 | 通过标准化工具调用执行任务 |
| 上下文靠手动复制粘贴 | 可按需动态读取上下文 |

---

## 三、MCP 可以做什么

不同的 MCP Server 会提供不同能力，常见场景包括：

- 读取设计稿、组件规范、页面结构
- 搜索代码、读取文件、生成代码
- 查询知识库、接口文档、产品文档
- 访问数据库、工单系统、项目管理平台
- 控制浏览器进行自动化测试或页面检查
- 调用企业内部服务或业务接口

以设计协作为例：

如果 AI 连接了设计平台的 MCP Server，它就不需要你手动截图、复制尺寸、描述颜色，而是可以直接读取设计稿的结构化数据，再辅助生成更贴近设计稿的代码。

---

## 四、MCP 的核心组成

一个典型的 MCP 体系，通常由三部分组成：

### 4.1 MCP Client

也就是使用 MCP 的 AI 客户端，例如：

- Cursor
- Claude Desktop
- Trae
- LingMa

客户端负责：

- 与用户对话
- 展示可用工具
- 把 AI 的工具调用请求转发给 MCP Server

### 4.2 MCP Server

MCP Server 是真正提供能力的一端。  
它通常封装了某个系统、平台或服务，并把这些能力以标准格式暴露给 AI。

例如一个设计平台的 MCP Server，可能提供：

- 获取页面 DSL
- 获取节点元信息
- 获取组件说明
- 查询设计资源链接

### 4.3 Tools / Resources / Prompts

MCP 中常见的能力类型包括：

- **Tools**：可被调用的操作，例如“搜索文档”“读取设计稿”“创建任务”
- **Resources**：可被读取的资源，例如文档、配置、知识条目
- **Prompts**：可复用的提示模板，用来规范某类任务的输入方式

对使用者来说，可以把它理解为：

- `Tools` 更像“功能按钮”
- `Resources` 更像“可读取的数据”
- `Prompts` 更像“预设工作模板”

## 五、MCP 是如何工作的

可以把 MCP 理解成 AI 与外部世界之间的桥梁，流程通常如下：

1. 用户提出需求，例如“根据设计稿生成一个登录页”。
2. AI 判断当前任务需要调用哪些外部能力。
3. 客户端将请求发送给对应的 MCP Server。
4. MCP Server 返回结构化结果，例如 DSL、文档内容、节点属性等。
5. AI 基于这些结果继续分析、生成代码或给出结论。

整个过程中，AI 并不是“直接懂了所有信息”，而是通过 MCP **按需获取上下文**。

---

## 六、MCP 和 API 有什么区别

MCP 不是用来替代 API，而是让 AI 更容易、更标准地使用 API 和外部能力。

可以这样理解：

- **API**：面向程序与程序之间的调用接口
- **MCP**：面向 AI 客户端与工具生态之间的标准协议

很多 MCP Server 的底层其实仍然在调用 API，只是对 AI 来说，它不再需要理解每个平台都不一样的接入方式，而是通过统一协议来访问这些能力。

---

## 七、MCP 对开发工作的价值

对于开发者、设计协作者和产品团队，MCP 的价值通常体现在以下几个方面：

- **减少手工搬运上下文**：不必频繁复制设计稿、文档、接口说明
- **提升回答准确性**：AI 可以基于实时数据回答，而不是只靠猜测
- **增强自动化能力**：AI 可以读取、查询、分析甚至执行部分操作
- **改善协作效率**：设计、研发、文档和测试可以通过统一入口协同
- **更适合复杂项目**：当项目依赖多个系统时，MCP 能显著提升 AI 可用性

---

## 八、在 Cursor 里如何理解 MCP

在 Cursor 这类工具中，可以把 MCP 理解为：

- 给 AI 接入“外部插件能力”的方式
- 让 AI 不只会写代码，还能读取外部上下文
- 让 AI 可以基于真实项目环境执行更贴近实际的任务

例如接入设计平台 MCP 后，你可以直接说：

- “读取这个设计稿的页面结构”
- “根据设计稿生成 Vue 页面”
- “提取颜色、间距、组件层级”
- “对照设计稿检查当前页面是否缺少元素”

这时 AI 的输出通常会更具体，也更接近实际需求。

---

## 九、结合本项目可以怎样理解

如果本项目接入了 **MasterGo MCP**，那么 AI 就可以在当前项目里：

- 读取 MasterGo 设计文件的结构化信息
- 获取组件、页面、节点相关数据
- 帮助生成前端页面或还原设计细节
- 辅助检查页面与设计稿之间的差异

也就是说，**MCP 让“设计稿 -> 代码”的过程变得更自动化、更可验证**，而不只是依赖人工描述。

---

## 十、一句话总结

**MCP 是一种让 AI 安全、标准化地连接外部工具和上下文的协议。**

它的意义不只是“多一个接口”，而是让 AI 从“只会聊天”升级为“能结合真实环境完成任务”的工作助手。
